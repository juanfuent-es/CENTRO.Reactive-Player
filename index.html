Estructura | Requisitos

  1. Arquitectura y Código Estructurado

    • Organización de Archivos: Estructura de directorios convencional, naming correcto (sin espacios, caracteres especiales), ordenamiento lógico de archivos y eliminación de código/archivos no utilizados.
    • Calidad del Código: Arquitectura clara con funciones separadas y definición correcta de variables, clases y funciones.
    • Programación Orientada a Objetos (POO): Mínimo una clase propia que organice la lógica de visualización, gestión de partículas, o el control del propio reproductor.

  2. Funcionalidad del Reproductor

    • Contenido: Cargar al menos tres pistas de audio.
    • Identidad: Incluir el Título del proyecto y una Pantalla de bienvenida tipo preloader que unifique narrativa y proceso de carga.
    • Controles Esenciales: Implementación completa de play/pause, anterior/siguiente, volumen y barra/indicadores de progreso.

  3. Visualización y Diseño Reactivo

    • Visualización Coherente (ondas, barras, partículas, espectro, objetos, etc.) que refleje directamente el Procesamiento de Audio (Amplitud o FFT).
    • Uso de Estructuras de Datos: Uso significativo de vectores/arrays y correcto uso de tipos de datos. (ej: para gestionar partículas, dimensiones, posiciones, colores dinámicos, o historial de datos sonoros).
    • Diseño Dinámico: Implementación de paletas de color diferenciadas por canción, aplicadas dinámicamente a la interfaz del player.

Metadata (Requisitos)

  • Incluye un título de página (`<title>`).
  • Define el idioma del documento (`<html lang="...">`).
  • Agrega un favicon compatible con navegadores modernos y *fallback* (realfavicongenerator.net).
  • Configura metadata Open Graph para mejorar previsualizaciones en redes sociales.

Repositorio en GitHub

El código debe alojarse en un repositorio público en **GitHub**:

  • Asegura que el repositorio sea **público**.
  • Incluye un `README.md` con descripción y enlaces relevantes.
  • Realiza *commits* descriptivos (evita “update” o “fix”).
  • **Publica el proyecto en GitHub Pages (obligatorio).**
  • Incluye el enlace al sitio *live* en la descripción del repositorio.

Recomendaciones

Mejora la experiencia considerando:

  • Utiliza archivos de audio en formato .mp3.
  • Personalizar los enlaces con estilos distintivos.
  • Evitar enlaces rotos o que requieran autenticación.

Rúbrica de Evaluación (100%)

1. Funcionalidad · 35%

  • 10% El audio carga correctamente y se reproduce sin errores.
  • 10% Controles esenciales implementados (play/pause, anterior/siguiente, ...).
  • 15% Visualización reactiva coherente (amplitud, FFT, ritmo, etc.).

2. Buenas Prácticas · 30%

  • 10% Uso correcto de clases propias.
  • 10% Uso significativo de vectores/arrays.
  • 10% Estructura clara: variables definidas y funciones separadas.

3. Diseño visual y experiencia · 20%

  • 10% Estética clara y consistente.
  • 10% Interacción fluida, transiciones limpias y paleta adecuada.

4. Documentación y presentación · 10%

  • 5% README claro con instrucciones, concepto visual y capturas/GIF.
  • 5% Presentación final explicando decisiones de diseño y aspectos técnicos.

5. Publicación y entrega · 5%

  • 5% Proyecto publicado y funcionando en GitHub Pages.

Entrega

El proyecto final debe estar **publicado, funcionando y accesible** a través de **GitHub Pages**.

Asegúrate de que el repositorio cuente con el `README.md` y el enlace directo al proyecto *live*, conforme a los requisitos de la sección **"Repositorio en GitHub"**.
