Introducción

El propósito de este ejercicio es presentar un micrositio que acompañe y explique tu Reproductor Reactivo: interfaz, controles, visualización sonora y concepto detrás de la experiencia.

Usa este espacio para documentar decisiones técnicas y diseñar una narrativa clara sobre tu reproductor. Considera incluir:

  1. Título del proyecto.
  2. Pantalla de bienvenida tipo preloader que unifique narrativa y carga.
  3. Al menos tres pistas de audio.
  4. Controles: play/pause, anterior/siguiente.
  5. Mínimo una clase propia que organice la lógica de visualización.
  6. Uso significativo de vectores/arrays (partículas, dimensiones, posiciones, etc.).
  7. Paletas de color diferenciadas por canción, aplicadas dinámicamente al reproductor.
  8. Arquitectura clara con funciones separadas.
  9. Entrega publicada en GitHub Pages.

Estructura del proyecto

Integrar variables, funciones, clases, instancias y vectores con conceptos multimedia: Carga de recursos, animación, eventos del usuario y procesamiento de audio con p5.sound u otras APIs.

Estructura tu entrega en tres capas: narrativa/visual, lógica de reproducción y documentación. Cada capa debe reforzar la experiencia y mostrar decisiones conscientes.

  • Cargar al menos tres pistas de audio.
  • Controles: play/pause, volumen y barra de progreso.
  • Al menos una visualización reactiva (ondas, barras, partículas, figuras, espectro, etc.).
  • Mínimo una clase propia que organice la lógica de visualización.
  • Uso significativo de vectores/arrays (partículas, buffers, historial).
  • Pantalla de bienvenida tipo preloader que unifique narrativa y carga.
  • Paletas de color diferenciadas por canción, aplicadas dinámicamente al player.
  • Función de captura (screenshot) para documentar visuales directamente desde la UI.
  • Arquitectura clara con funciones separadas.
  • Entrega publicada en GitHub Pages.

Metadata

  • Incluye un título de página.
  • Define el idioma del documento.
  • Agrega un favicon compatible con navegadores modernos y fallback (realfavicongenerator.net).
  • Configura metadata Open Graph para mejorar previsualizaciones.

Repositorio en GitHub

El código debe alojarse en un repositorio público en GitHub:

  • Asegura que el repositorio sea público.
  • Incluye un README.md con descripción y enlaces relevantes.
  • Realiza commits descriptivos (evita “update” o “fix”).
  • Publica el proyecto en GitHub Pages.
  • Incluye un enlace al sitio en la descripción del repositorio.

Tips

¿No sabes por dónde empezar? Considera:

  • Crea un moodboard para definir el estilo.
  • Usa Adobe Color o Coolors para paletas.

Recomendaciones

Mejora la experiencia considerando:

  • Evitar enlaces rotos o que requieran autenticación.
  • Personalizar los enlaces con estilos distintivos.
  • Incluir una sección “Sobre mí” o un archivo humans.txt.

Rúbrica de evaluación (100%)

1. Funcionalidad del reproductor · 35%

  • 10% El audio carga correctamente y se reproduce sin errores.
  • 10% Controles esenciales implementados (play/pause, volumen, progreso).
  • 15% Visualización reactiva coherente (amplitud, FFT, ritmo, etc.).

2. Uso adecuado de programación · 30%

  • 10% Uso correcto de clases propias.
  • 10% Uso significativo de vectores/arrays.
  • 10% Estructura clara: variables definidas y funciones separadas.

3. Diseño visual y experiencia · 20%

  • 10% Estética clara y consistente.
  • 10% Interacción fluida, transiciones limpias y paleta adecuada.

4. Documentación y presentación · 10%

  • 5% README claro con instrucciones, concepto visual y capturas/GIF.
  • 5% Presentación final explicando decisiones de diseño y aspectos técnicos.

5. Publicación y entrega · 5%

  • 5% Proyecto publicado y funcionando en GitHub Pages.

Entrega

El proyecto debe estar publicado en GitHub Pages con README y botón accesible al proyecto live.
